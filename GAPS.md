The code-side half of OT-16 (checking the send result before marking sent) is fixed; this half isn't something a repo change can close.

## Flagged, deliberately not fixed (real, but out of this task's own scope)

1. **`archetype_relationship` table is empty in production (0 rows).** `getAdjacentArchetypes()` silently degrades `archetype_range`/`alternatives` RAG focus to single-archetype-only — it only falls back to its hardcoded adjacency map on a thrown error, and an empty result set doesn't throw. Still returns a non-empty catalog either way (2 and 4 coffees respectively), so it doesn't fail the RAG smoke test's own literal bar, but it's a real quality gap. Needs either real adjacency data populated, or a code change so `getAdjacentArchetypes()` treats "empty" the same as "errored." Not fixed — populating real data or changing fallback semantics is design work, not a verification-pass fix.
2. **No `firestore.indexes.json`/`firebase.json` exists anywhere in this repo.** Every Firestore composite index this project has ever needed has been created ad hoc (via a failing query's own console link, or — this pass — directly via `gcloud`). Nothing declares these as code, so a fresh environment or a Firestore data-reset would silently reintroduce the exact `RECOMMENDATION_MISS`/`outcomeTracker` bug class this pass just fixed. Standing up a `firebase.json` + index-deploy step is real infrastructure work, judged out of scope for a verification pass — flagged instead, same as `schema.sql`'s own "views are schema, not live-only" prevention note (HOME_TASK_7b/S84) for a different config-drift class.
3. **One soft, debatable voice-pass finding, not auto-fixed.** A turn 4 Liam reply ("floral because it actually appeals to you, or because it seemed like a safe bet?") rhymes with S32's banned WHY-question pattern without using its literal phrasing. Judged genuinely ambiguous — flagged for whoever does the next monthly transcript read (S33's own cadence) rather than editing the prompt off one instance.
4. **E5 welcome email token-allowance wording** — still open from S72 (Task 3). Not re-checked this pass; still needs the reword to full-sommelier-access framing before it ships.
