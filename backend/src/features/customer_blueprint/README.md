# Customer Blueprint — brief series

Target architecture for the customer side of the database: three classes of data (operating tables, master data, facts), one writer per fact, reads only through views, integrity held by the database, the code, the build and the boot. Reference doc: the **Liam Recommendation Map** artifact (version 7, 2026-09-27; decisions D1–D21 on the page). Decisions are settled; briefs implement them and do not re-open them.

Situation this series was written for: 145 profiles, 122 quiz sessions, real orders; the same customer fact is copied into up to seven stores by fire-and-forget writes from route handlers; half the facts live in Firestore; one login role both applies `schema.sql` at boot and serves every request. Because there is live data, the plan is **coexistence, not a clean cut**: each new fact goes live with its old store still written, a daily comparison reports disagreements, and the old writer is removed after N clean days.

Run in order. Each brief is deployable on its own and leaves the system working. Liam's briefs (L1–L3, in `features/ai_agent_liam/recommendation/`, not yet written) wait for C3.

**Naming convention (Dana, 2026-09-26/27):** `coffee_*` = catalog (master data); `customer_*` = a fact about a customer, append-only by definition; no prefix = operating table (mutable, runs the system); `v_customer_*` = one customer's facts or current state, joined; `v_palate_*` = a versioned read over facts. `quiz_session`, `quiz_session_interpretation`, `"order"` and `order_line_item` keep their names and are listed explicitly in the fact grant block.

House rules that apply to every brief here: one writer per fact, via `customerFacts.record.*()`; no UPDATE or DELETE on a fact, enforced by the database role; derivations used by two or more readers are views; constraints, not comments; integrity green is part of done; every brief updates the ownership table in `WHAT_WE_BUILT_DB.md`; backfills and prod steps run by Claude Code under the owner role with STOP checkpoints, never by hand.
