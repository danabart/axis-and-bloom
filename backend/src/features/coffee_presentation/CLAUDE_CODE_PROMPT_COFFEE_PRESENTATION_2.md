## Why (Dana, 2026-10-23/24)

1. **Every C&N coffee says "significantly less body and significantly less bitterness than your usual Chocolate & Nutty profile."** `useCompatibility.tsx getDimensionComparison` compares the coffee's pooled cupping range to `archetype_vector`, the May 2026 assumed targets seeded from a JPG (`db/seeds/archetype_vectors.sql`: C&N body 10 to 13, bitterness 7 to 11). Coado cups at body 7 and bitterness 3.5. The sentence is the abandoned distance model talking (Dana's standing rule, 2026-09-26: nothing developed on assumed weights; review §3.2). The thresholds 1.5 and 4 are literals in the component.
2. **Each coffee has three descriptions that say the same thing.** Brief 1 generates `ai_summary`, `surprise_note` and `three_voice_story` from the same roaster voice with the same rules; Flavor Intelligence stacks all three and the position card's teaser is the surprise note's first sentence. Dana: one description per coffee.
3. **Quieta Non Movere (Fabricator, 2917) sits on the C&N dial, slot 1, with match archetype Fruity.** Its line reads "Citrus Fruit / a hint of nutty / cocoa: hazelnut" under a Chocolate & Nutty heading, its texts are citrus-led, and `/api/coffees/2917/story` returns `dialPosition: null` because the slot's archetype disagrees with the match. Dana decided Fabricator → C&N light on 2026-10-21 after the Balance cupping (session of that date); only the placement happened.

## Decisions (Dana, 2026-10-24). Do not re-open.

1. **The sentence compares a coffee to a reference profile, and the reference is swappable.** Today the reference is the archetype's actual coffees. Later it is the customer's own liked bags (Dana: "in the future we should also compare it to the customer bag if they liked it; I don't want to rule it out"), which `v_customer_bag_attribution` + `v_customer_feedback_current` + `v_palate_shared_traits` already describe. So the comparison lives in one backend read with a `reference` argument: `{ kind: 'archetype', archetype }` built now, `{ kind: 'customer_bags', canonicalUserId }` declared in the type and returning `null` with reason `not_built` until there is order data. Nothing from the frontend decides what the reference is.
2. **Archetype reference = the pooled midpoints of the archetype's active coffees, leave-one-out.** New view `v_archetype_dimension_profile`: one row per archetype × dimension from the current match assignments (`coffee_archetype_assignment` where `superseded_at IS NULL`) of active coffees joined to `v_coffee_dimension_range`: `avg_midpoint`, `min_midpoint`, `max_midpoint`, `coffee_count`, `coffee_ids` (int[]). The read excludes the coffee being compared from its own archetype's profile before averaging (with two coffees, comparing one to an average that includes itself says nothing). Why not `v_archetype_dimension_comparison`: it is built from `archetype_vector` (a dimension or archetype missing there never appears, the join is `md5(name)`, and it carries the target columns); it stays as the admin's hypothesis-vs-actual view and is not read by anything customer-facing. No other existing object holds per-archetype actual profiles (checked `CATALOG.md`: `v_archetype_vectors`, `v_archetype_dimension_comparison`, `v_coffee_dimension_range_calibrated`, `v_palate_shared_traits`).
3. **The sentence renders only when the reference has enough coffees.** `param('archetype_profile_min_coffees')`, seeded **4**, counted after leave-one-out. Today every archetype has 1 or 2 active cupped coffees, so no sentence renders anywhere; it returns on its own as the catalog grows. The badge (wheelhouse / worth exploring / stretch) stays: it reads `v_archetype_adjacency`, real data.
4. **Thresholds are parameters.** `param('dimension_delta_slight')` **1.5** and `param('dimension_delta_significant')` **4**, same unit as the 0 to 15 scale, editable on the Evidence parameters card like the others. No number in the component or the read.
5. **`archetype_vector` is a seed hypothesis with no customer-facing reader.** `comments.sql` Purpose says so; `GET /api/axis/vectors` and `frontend/.../archetypeVectors.ts` are removed (their only reader was the sentence). The table and the seed stay (nothing deleted). `getDialSuggestion` still reads it for the slot suggestion (review 5.1): **not touched here**, listed in the closing report as the remaining reader.
6. **One description per coffee: `three_voice_story`.** Customer surfaces render it alone: the reveal panel (already), Flavor Intelligence's `TastingNotes variant='full'` (drop the summary and surprise blocks), the position card teaser (always the signature line from brief 1; the surprise-note branch goes), the compare overlay if it shows prose. The backfill and `refresh-content` stop generating `ai_summary` and `surprise_note`; the columns and their current values stay (nothing deleted), `comments.sql` marks both `retired from customer surfaces, brief 2`. Liam's RAG (`sommelierRag.ts`: the `Tasting note:` line and the editorial-completeness score) reads `three_voice_story` instead of `ai_summary` / `surprise_note`. The "What the customer sees" admin block shows the one text. The header above the prose reads **In the roaster's words** instead of "Three voices", and its legend goes (there are no three voices any more: the roaster leads, customers add, we only confirm).
7. **Fabricator (2917) match archetype → `chocolate_nutty`**, through the assignment door `catalogService.setMatchArchetype`: `source 'cupping'`, `sessionId` = the cupping session dated 2026-10-21 (looked up by date, never a literal id), `confidence 'medium'`, `notes 'Dana 2026-10-21: C&N light, slot 1; bitterness and a grippy texture, not body; roaster classification Fruity kept as evidence'`, `basis` composed by `composeBasis` from the current evidence. One-off loader like brief 1's award (`load/setMatch2917.ts`, `--expect-db`, dry run, skips when the current match already is `chocolate_nutty`). After it: `refresh-content` on 2917 so its text follows the new signature line ("Hazelnut / a hint of fruity: citrus fruit; a hint of spices: cinnamon", expected, assert the read), and `/api/coffees/2917/story` returns a non-null `dialPosition`. The roaster's `proposed_archetype` (Fruity) stays as the evidence row it is.
8. **No table change. One new view. Three parameter rows. One catalog write (decision 7), through the door, on prod only after Dana's go. Nothing deleted.**
