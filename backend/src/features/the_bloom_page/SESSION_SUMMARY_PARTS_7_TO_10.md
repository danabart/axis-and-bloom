## Local testing pattern (Cloud SQL + Playwright)

See memory `axis-and-bloom-local-cloudsql-testing` for the full Auth Proxy setup. Additions from this session:
- **`backend/.env` needs `RESEND_API_KEY=re_local_placeholder`** (or any non-empty value) to boot locally — `backend/src/routes/auth.ts` constructs a `Resend` client at import time and throws synchronously if the key is missing, crashing `tsx watch` before it binds the port. `.env` is gitignored; this placeholder is a permanent-enough local convenience, not a one-off.
- **`tsx watch` does not reload on `.env` changes** (only watches `.ts` sources) — after editing `.env`, kill and restart the `node.exe` process manually.
- The backend's `express-rate-limit` (200 req / 15 min) gets hit fast during repeated local Playwright runs against the same session — if `curl`/Playwright starts getting 429s, just restart the backend process to reset the in-memory counter, don't debug it as a real bug.
- Simulating a drag-based UI control (the Bloom Dial's wheel) from Playwright: compute the wheel's bounding box, then `page.mouse.move` to a point at the top of the circle (angle 0) → `mouse.down()` → move through a midpoint → move to a point at the bottom (angle 180, a clean +180° delta) → `mouse.up()`. Confirm the resulting position via the widget's own live label text, not just an assumed index.
- Always clean up afterward: stop the Auth Proxy, backend, and frontend dev server processes, delete the temp BOM-stripped service account key, delete scratch Playwright scripts/screenshots.
